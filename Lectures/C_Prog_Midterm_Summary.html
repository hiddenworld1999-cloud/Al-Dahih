📦 المفاهيم الأساسية: البرمجة ومراحل حل المشكلة

البرمجة: هي أخذ مدخلات (Input)، ومعالجتها جوه "صندوق أسود" (Black Box)، وإخراج مخرجات (Output) لحل مشكلة.

مراحل حل المشكلة (Problem Solving):

  1. فهم المشكلة (Problem Understanding): بتفهم المطلوب إيه بالظبط قبل ما تبدأ.
  2. تخطيط الحل (Planning): بتصمم خوارزمية (Algorithm) أو مخطط تدفق (Flowchart) أو خوارزمية زائفة (Pseudocode).
  3. تنفيذ الخطة (Implementation): بتحول الخطة لكود بلغة برمجة زي Python أو Java.
  4. فحص النتيجة (Testing/Verification): بتجرب الكود وتصلح الأخطاء (Debugging) عشان تتأكد إنه شغال صح.

🧮 الخوارزمية و Big-O

الخوارزمية (Algorithm):

هي خطوات محددة ومنطقية لحل مشكلة. شروطها:

  • تتكتب بلغة إنجليزية بسيطة.
  • كل خطوة دقيقة وغير غامضة.
  • متتكررش بلا نهاية، ولازم تنتهي بعد عدد محدود من الخطوات.
  • النتائج بتظهر بعد انتهاء الخوارزمية بس.

عوامل تقييم جودة الخوارزمية: الوقت (أقل وقت = أفضل)، الذاكرة (أقل استهلاك = أفضل)، الدقة (تعطي نتائج صح).

Big-O Notation (تحليل كفاءة الخوارزميات):

هي طريقة رياضية بنقيس بيها كفاءة الخوارزمية (سرعة تنفيذها وحجم الذاكرة اللي بتستهلكها). كل ما الـ Big-O أصغر، كل ما الخوارزمية أفضل. مثال: البحث الخطي O(n)، البحث الثنائي O(log n).

📝 Pseudocode ومكونات الخوارزمية

الخوارزمية الزائفة (Pseudocode):

هي كتابة الكود بلغة بسيطة جداً تشبه الإنجليزية العادية. ميزتها إنك بتركز على "المنطق" مش على قواعد اللغة المعقدة (زي الفواصل المنقوطة)، وعيبها إنها مش رسمية ومفيش شكل موحد ليها. قواعدها: الكلمات المفتاحية تبدأ بحرف كابيتال (IF, ELSE, READ)، وسطر واحد لكل أمر.

مكونات الخوارزمية (Elements of Algorithm):

  • Statements (العبارات): جمل بسيطة زي الإدخال والتعيين والإخراج.
  • States (الحالات): قيم المتغيرات في لحظة معينة.
  • Control Flow (تدفق التحكم): تسلسلي، شرطي، تكراري.
  • Functions (الدوال): كتلة كود قابلة لإعادة الاستخدام.

أنواع التعليمات (Statements):

  • Input Statements (إدخال): زي READ a, b (بنقرأ قيم من المستخدم).
  • Output Statements (إخراج): زي PRINT c (بنطبع قيمة على الشاشة).
  • Assignment Statements (تعيين): زي c = a + b (بنخزن قيمة في متغير).
  • Comment Statements (تعليقات): زي // This is a comment (ملاحظات مش بتتنفذ، بتشرح الكود بس).

🔄 Main / Sub Functions و Control Flow

Main Function و Sub Function:

  • Main Function (الدالة الرئيسية): هي نقطة البداية اللي البرنامج بيبدأ ينفذ منها. بتستدعي الدوال التانية.
  • Sub Function (الدالة الفرعية): دالة بتعمل وظيفة محددة، وبتتنادى من الـ Main أو من دوال تانية.
💡 مثال على الاستدعاء (من المحاضرة):
Main Function: Start → Call add() → Stop
Sub Function add(): Function start → Get a, b → c = a + b → Print c → Return

تدفق التحكم (Control Flow):

  • Sequential (تسلسلي): خطوة ورا خطوة.
  • Selection (شرطي): IF Condition → ELSE (زي لو الدرجة ≥ 50 يبقى ناجح).
  • Looping (تكرار): تكرار أمر معين لحد ما شرط يتحقق (زي WHILE).

🔤 المتغيرات (Variables) والعمليات (Operators)

قواعد تسمية المتغيرات:

  • يبدأ بحرف (A-Z or a-z) أو شرطة سفلية (_). (مينفعش يبدأ برقم).
  • مينفعش يحتوي على مسافات أو رموز زي (- أو @).
  • حساس لحالة الأحرف (Case-Sensitive): myVar غير myvar.
  • مينفعش يكون كلمة محجوزة (Reserved Keyword) زي if أو for.
  • يفضل استخدام Snake Case (زي user_name).

🔁 الحلقات (Loops)

  • for loop: بتتكرر عدد مرات معروف. مثال: for x in range(2, 6) هتطبع 2, 3, 4, 5.
  • while loop: بتفضل تتكرر طول ما الشرط صح.
  • break: بتنهي الحلقة بالكامل.
  • continue: بتتخطى التكرار الحالي وتكمل اللي بعده.

💻 لغات البرمجة (Levels & Paradigms)

  • High-level (عالية المستوى): سهلة وقريبة من لغة الإنسان زي Python وJava وC++.
  • Low-level (منخفضة المستوى): قريبة من لغة الآلة زي Assembly وMachine Language.
  • Procedural (إجرائي): بيعتمد على الدوال خطوة بخطوة (زي C).
  • OOP (موجه للكائنات): بيعتمد على الفئات (Classes) والكائنات (Objects) زي Python وJava.

📚 مقدمة في هياكل البيانات (Data Structures)

هي طرق تخزين وتنظيم البيانات عشان نقدر نوصلها ونعالجها بكفاءة. بتتقسم لـ:

  • Linear (خطية): البيانات متخزنة بشكل متسلسل (زي المصفوفة، الطابور، المكدس، القائمة المرتبطة).
  • Non-linear (غير خطية): العلاقات بين البيانات معقدة (زي الشجرة Tree والرسم البياني Graph).

⚙️ الدوال (Functions)

كتلة كود بتعمل شغل معين، بنكتبها مرة ونستخدمها كتير. بتتعرف بـ def.

def add(a, b):
    return a + b

result = add(3, 5)
print(result)  # Output: 8

Functions with Parameters & Return Values:

الدالة ممكن تاخد Parameters (مدخلات) وترجع Return Value (ناتج).

# دالة بترجع مربع الرقم
def square(number):
    return number * number

print(square(4))  # Output: 16

# دالة بترجع ناتج الضرب
def multiply(a, b):
    return a * b

print(multiply(3, 4))  # Output: 12

# دالة بترجع True لو الرقم زوجي
def is_even(number):
    return number % 2 == 0

print(is_even(4))  # Output: True

الفرق بين Parameters و Arguments:

Parameters: المتغيرات اللي بتتكتب في تعريف الدالة (زي a, b).

Arguments: القيم الفعلية اللي بنبعتها عند استدعاء الدالة (زي 3, 5).

🔄 دورة حياة تطوير البرمجيات (SDLC)

يعني إيه SDLC؟ هي منهجية منظمة بنتبعها عشان نعمل برنامج بجودة عالية. بتمر بـ 7 مراحل:

  1. التخطيط (Planning): تحديد أهداف المشروع والميزانية والجدول الزمني (باستخدام SWOT أو Jira).
  2. التحليل (Analysis): بنجمع متطلبات العميل في وثيقة اسمها SRS (بتشمل: متطلبات وظيفية Functional [زي تسجيل الدخول]، وغير وظيفية Non-Functional [زي الأمان والسرعة]، وقيود Constraints [زي اللغة والوقت]).
  3. التصميم (Design): بنصمم شكل النظام، قاعدة البيانات (Database Schema)، وواجهات المستخدم (UI/UX) باستخدام أدوات زي Figma أو UML.
  4. التطوير (Development): بنكتب الكود الفعلي باستخدام لغات زي Python.
  5. الاختبار (Testing): بنتأكد إن مفيش أخطاء (اختبار وحدات Unit، تكامل Integration، نظام System، ومستخدم UAT).
  6. النشر (Deployment): بنطلع البرنامج للمستخدمين (يا إما Phased بالتدريج، أو Big Bang مرة واحدة).
  7. الصيانة (Maintenance): إصلاح أخطاء (Corrective)، تحسين أداء (Preventive)، أو إضافة ميزات جديدة (Adaptive).

⚙️ نماذج ومنهجيات SDLC (مهم جداً في الامتحان)

النموذج (Model) الخصائص متى نستخدمه؟
Waterfall (الشلال) خطي ومتسلسل، كل مرحلة بتخلص 100% قبل اللي بعدها، توثيق شامل، لكنه غير مرن. المشاريع ذات المتطلبات الثابتة والواضحة (زي أنظمة الحسابات وقواعد البيانات).
Iterative (التكرار) بنعمل نسخة صغيرة ونختبرها وناخد رأي العميل، وبنكرر لحد ما نوصل للنسخة النهائية. مرن جداً. المشاريع الكبيرة اللي متطلباتها غامضة أو بتتغير. (مش مناسب للمشاريع البسيطة جداً).
RAD (التطوير السريع) بيعتمد على النماذج الأولية (Prototypes) ومشاركة العميل المستمرة، وقت قليل جداً (أسابيع). الشركات اللي محتاجة تطلع للسوق بسرعة (زي المتاجر الإلكترونية).
Spiral (الحلزوني) حلقات متوسعة، بيجمع بين التكرار والشلال، ويركز جداً على إدارة المخاطر (Risk Analysis). المشاريع الضخمة جداً وعالية المخاطر. (مكلف ومعقد).
V-Model نسخة محسنة من الشلال، كل مرحلة تطوير بيقابلها مرحلة اختبار (Verification & Validation). المشاريع اللي محتاجة جودة عالية وأمان (زي الأنظمة الطبية أو العسكرية).
Agile (أجايل) مرن جداً، بيعتمد على تكرارات قصيرة اسمها Sprints (من أسبوعين لشهر)، وتسليم مستمر للميزات. تطبيقات الويب والموبايل الحديثة اللي بتتطور باستمرار.
💡 ملاحظة للامتحان: لو السؤال قال "متطلبات غير واضحة ومتغيرة" → الإجابة Agile أو Iterative. لو قال "مخاطر عالية" → Spiral. لو قال "سريع ونماذج أولية" → RAD. لو قال "متطلبات ثابتة" → Waterfall. لو قال "أنظمة طبية/عسكرية" → V-Model.

🧬 البرمجة الشيئية (OOP): المفاهيم الأساسية

المفاهيم الأساسية:

  • Class (الفئة): هي القالب أو التصميم (زي تصميم العربية).
  • Object (الكائن): هي النسخة الحقيقية من القالب (زي عربية أحمد الحمراء).
  • __init__ (المنشئ): دالة خاصة بتشتغل أوتوماتيك أول ما نعمل Object، وبتديه القيم الأساسية.

الفرق بين Properties و Methods:

  • Properties (الخصائص): المتغيرات اللي بتخزن البيانات جوه الكائن (زي الاسم والسن).
  • Methods (الدوال): الأفعال أو الوظائف اللي الكائن يقدر يعملها (زي إنه يرحب أو يحتفل بعيد ميلاده).

إنشاء Object واستخدام Methods:

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def greet(self):
        print("Hello, my name is " + self.name)

p1 = Person("Ali", 25)
p1.greet()  # Output: Hello, my name is Ali

تعديل Property باستخدام Method:

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def celebrate_birthday(self):
        self.age += 1
        print(f"Happy birthday! You are now {self.age}")

p1 = Person("Ali", 25)
p1.celebrate_birthday()  # Output: Happy birthday! You are now 26

🏛️ أركان OOP الأربعة

  1. الوراثة (Inheritance): كلاس جديد (Child) بيورث خصائص كلاس قديم (Parent). بنستخدم super().__init__() عشان ننادي على الأب.
  2. التغليف (Encapsulation): إخفاء البيانات وحمايتها. بنخلي المتغير "خاص" (Private) بعلامتين (_ _) زي __age، ومينفعش نوصله من بره غير من خلال دالة get تقرأه، ودالة set تغيره.
  3. تعدد الأشكال (Polymorphism): نفس اسم الدالة (زي move)، بس كل كلاس بينفذها بطريقته (العربية بتدور Drive، المركب بتبحر Sail).
  4. التجريد (Abstraction): إخفاء التفاصيل المعقدة وتقديم واجهة بسيطة. بنستخدم كلاس مجرد (ABC) ومينفعش نعمل منه Object مباشرة.

كود يوضح الوراثة والتغليف:

class Person:
    def __init__(self, name, age):
        self.name = name
        self.__age = age  # Private

class Student(Person):  # Inheriting
    def __init__(self, name, age, year):
        super().__init__(name, age)
        self.graduationyear = year

🔐 Flask وتسجيل الدخول

المصادقة (Authentication) vs التفويض (Authorization):

  • Authentication: "من أنت؟" (بتتأكد من الهوية بالـ Username والـ Password).
  • Authorization: "مسموحلك تعمل إيه؟" (بتشوف الصلاحيات، هل أنت Admin ولا User عادي).

خطوات التسجيل (Registration Flow):

Submit (إرسال) → Validate (تحقق) → Hash (تشفير) → Store (تخزين) → Redirect (تحويل).

خطوات تسجيل الدخول (Login Flow):

Submit → Find User (دور عليه) → Verify (قارن الباسورد بالـ Hash) → Session (احفظ الـ ID) → Redirect.

مهم جداً للأمان:

  1. متخزنش الباسورد "Plain Text" أبداً. لازم تخزنه كـ Hash باستخدام دالة زي generate_password_hash.
  2. الباسورد بيتشفر بـ Salt (عشان لو مستخدمين ليهم نفس الباسورد يطلعوا Hash مختلف).
  3. عشان نحمي من هجمات SQL Injection، بنستخدم علامات الاستفهام ? في استعلامات الداتابيز.
  4. لو تسجيل الدخول فشل، بنطلع رسالة واحدة عامة: "Invalid username or password" عشان المخترق ميعرفش مين اليوزر الصح.
  5. الـ HTTP Stateless (بينسى)، عشان كده بنستخدم الـ Session عشان السيرفر يفتكر المستخدم.

💻 أكواد Flask المهمة

كود تسجيل الدخول (Login Route):

# Login Route
user = get_db().execute(
    "SELECT * FROM users WHERE username = ?", (username,)
).fetchone()

if user is None or not check_password_hash(user["password_hash"], password):
    flash("Invalid username or password.")
else:
    session.clear()
    session["user_id"] = user["id"]
    return redirect(url_for("dashboard"))

الشرح: بنجيب المستخدم من الداتابيز بـ ?. لو مش موجود، أو الباسورد اللي دخلناه مش متطابق مع الـ Hash، بنطلع رسالة خطأ. لو تمام، بنفضي أي جلسة قديمة (session.clear())، وبنحفظ الـ ID بتاع المستخدم في الجلسة (session["user_id"])، وبعدين بنحوله للـ dashboard.

كود التسجيل (Register Route):

@app.route("/register", methods=["GET", "POST"])
def register():
    if request.method == "POST":
        username = request.form["username"].strip()
        email = request.form["email"].strip().lower()
        password = request.form["password"]

        if not re.fullmatch(r"\w{3,20}", username):
            flash("Username must be 3-20 letters, digits or underscores.")
        elif len(password) < 8:
            flash("Password must be at least 8 characters.")
        else:
            try:
                get_db().execute("INSERT INTO users (username, email, password_hash) VALUES (?, ?, ?)",
                    (username, email, generate_password_hash(password)))
                get_db().commit()
                return redirect(url_for("login"))
            except sqlite3.IntegrityError:
                flash("Username or email already exists.")

🛡️ الصفحات المحمية (Protected Pages) و Logout

كود الصفحة المحمية (Dashboard):

# Protected Page
@app.route("/dashboard")
def dashboard():
    if "user_id" not in session:
        return redirect(url_for("login"))
    user = get_db().execute("SELECT username FROM users WHERE id = ?", (session["user_id"],)).fetchone()
    return f"Welcome, {user['username']}!"

كود تسجيل الخروج (Logout):

# Logout
@app.route("/logout")
def logout():
    session.clear()
    return redirect(url_for("login"))
💡 الشرح: الصفحة المحمية بتتأكد الأول إن user_id موجود في الـ Session (Guard). لو مش موجود، بتحوله للـ login. الـ Logout بيمسح الجلسة بالكامل بـ session.clear() عشان السيرفر ينسى المستخدم.

ملخص الأمان في Flask:

  • تشفير الباسورد بـ generate_password_hash.
  • التحقق بـ check_password_hash.
  • استخدام ? في استعلامات SQL لمنع الـ SQL Injection.
  • حفظ user_id في الـ Session بعد تسجيل الدخول.
  • مسح الـ Session بـ session.clear() عند تسجيل الخروج.
