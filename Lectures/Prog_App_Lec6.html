🔐 يعني إيه Authentication و Authorization؟

1. Authentication (التحقق من الهوية):

سؤال بيقول "Who are you?" (مين انت؟). يعني بيتأكد إن الشخص اللي بيدخل ده هو فعلاً صاحب الحساب. وده بيتم عن طريق إنك تدخل الـ Username والـ Password (زي صفحة تسجيل الدخول).

2. Authorization (الصلاحيات):

سؤال بيقول "What may you do?" (مسموحلك تعمل ايه؟). بعد ما عرفنا مين انت، بنشوف صلاحياتك. مثلاً: هل انت Admin (مدير) وعندك صلاحية تمسح وتعرض؟ ولا مستخدم عادي بتشوف بس؟

💡 الخلاصة:
• Authentication: البوابة اللي بتثبت هويتك (زي ما تبص للكافيه وتقوله دي بطاقتي).
• Authorization: الصلاحيات اللي جواك بعد ما دخلت (زي ما تقوله أنا عايز أدخل الـ VIP بس).
🏗️ المكونات الثلاثة لأي نظام تسجيل دخول
المكون (Component) وظيفته (Role)
Client (المتصفح) بيعرض صفحة الـ HTML وبيبعت البيانات (Username & Password) في طلب (POST Request).
Server (سيرفر بايثون) بيستقبل البيانات، بيتحقق منها، بيعمل Hash للباسورد، وبيبدأ الـ Session.
Storage (قاعدة البيانات) بتخزن الـ Username، الإيميل، والـ Password Hash. عمرها ما بتخزن الباسورد الأصلي.

ملاحظة مهمة: المتصفح عمره ما بيكلم قاعدة البيانات مباشرة. السيرفر هو اللي بياخد القرار وبيتكلم مع الداتابيز.

🔄 خطوات التسجيل (Registration Flow)

لما مستخدم جديد بيعمل حساب، بيمر بـ 5 خطوات كلهم بيحصلوا على السيرفر:

  1. Submit (إرسال): المستخدم بيملا الفورم والمتصفح بيبعت POST request.
  2. Validate (تحقق): السيرفر بيتأكد إن الـ Username صح، الإيميل شكله صح، والباسورد طويل كفاية.
  3. Hash (تشفير): السيرفر بيحول الباسورد لـ "Salted Hash" وبيتخلص من الباسورد الأصلي.
  4. Store (تخزين): بيتم إدخال صف جديد في الداتابيز. لو الـ Username أو الإيميل متكرر، بيطلع Error.
  5. Redirect (تحويل): بيتم تحويل المستخدم لصفحة تسجيل الدخول.
💡 قاعدة ذهبية: كل الخطوات دي بتحصل على السيرفر. عمرك ما تعتمد على التحقق اللي بيحصل في المتصفح بس (لأنه ممكن يتلعب فيه).
🔑 خطوات تسجيل الدخول (Login Flow)

لما مستخدم قديم بيدخل، بيمر بـ 5 خطوات برضه:

  1. Submit (إرسال): المتصفح بيبعت الـ Username والـ Password (عبر HTTPS في المواقع الحقيقية).
  2. Find User (البحث عن المستخدم): البحث في الداتابيز باستخدام Parameterized Query (عشان نحمي من الاختراق).
  3. Verify (التحقق): مقارنة الباسورد اللي المستخدم كتبه بالـ Hash المتخزن في الداتابيز.
  4. Session (الجلسة): حفظ الـ User ID في الـ Session عشان السيرفر يفتكر المستخدم.
  5. Redirect (تحويل): تحويل المستخدم للـ Dashboard (لوحة التحكم).
💡 ملاحظة أمنية: لو فشل تسجيل الدخول، لازم تطلع رسالة واحدة بس: Invalid username or password (يعني من غير ما تقول له "الباسورد غلط" أو "اليوزر مش موجود")، عشان المخترقين ميعرفوش مين المستخدمين الموجودين أصلاً.

🛡️ متخزنش الباسورد عادي (Never Store Plain Passwords)

لو خزنت الباسورد Plain Text (زي ما هو):

لو الداتابيز اتسربت، كل الباسوردات هتتكشف مرة واحدة. والناس بتستخدم نفس الباسورد في مواقع تانية (فممكن يتسرقوا في كل حتة).

الحل: Salted Hash (تشفير مع ملح):

الباسورد بيتحول لشكل مش مفهوم (مثلاً: script:32768:8:1$iymy...$4038b7...). القيمة المتخزنة دي مستحيل ترجع للباسورد الأصلي. السيرفر بيقارن الـ Hash بس.

إيه اللي يخلي الـ Hash كويس؟

  • One-way (اتجاه واحد): تقدر تحسب الـ Hash من الباسورد، بس متقدرش تجيب الباسورد من الـ Hash.
  • Salted (ملح): بيتم خلط قيمة عشوائية، عشان الباسوردات المتشابهة تطلع Hash مختلف.
  • Slow on purpose (بطيء عن قصد): بياخد وقت في الحساب، عشان لو حد بيخمن ملايين الباسوردات ياخد وقت طويل جداً.
💡 في بايثون، بنستخدم generate_password_hash و check_password_hash (من مكتبة Werkzeug). متحاولش تخترع طريقة تشفير من دماغك.
🍪 الـ Sessions: إزاي السيرفر بيفتكرك؟

الـ HTTP هو بروتوكول Stateless (يعني كل طلب جديد مفيش فيه ذكرى للطلب اللي قبله).

بعد تسجيل دخول ناجح، Flask بيخزن الـ User ID في Cookie موقّع (Signed Cookie).
كل طلب جديد بعد كده بياخد الـ Cookie دي معاه، عشان السيرفر يعرف مين اللي بيكلمه.

  • POST /login -> السيرفر بيعمل Cookie اسمها session=.
  • GET /dashboard + Cookie -> السيرفر بيقرأ الـ user_id ويرد بـ 200 OK.

🗄️ الخطوة 1: جدول المستخدمين (The users Table)
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    email TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL
)
💡 الشرح سطر بسطر:
• CREATE TABLE IF NOT EXISTS users: بنقول للداتابيز "لو جدول users مش موجود، اعمله".
• id INTEGER PRIMARY KEY AUTOINCREMENT: ده رقم تعريفي لكل مستخدم، بيكبر لوحده (1, 2, 3...). وده اللي هيخزن في الـ Session.
• username TEXT UNIQUE NOT NULL: خانة الاسم، مينفعش تتكرر (UNIQUE) ومينفعش تكون فاضية (NOT NULL).
• email TEXT UNIQUE NOT NULL: نفس الكلام للإيميل.
• password_hash TEXT NOT NULL: خانة تخزين الباسورد المشفر. لاحظ مفيش خانة اسمها password بتخزن الباسورد الأصلي.

• re.fullmatch(r"\w{3,20}", username): بنستخدم Regular Expression عشان نتأكد إن الاسم من 3 لـ 20 حرف (حروف أو أرقام أو شرطة سفلية).
• elif len(password) < 8:: بنتأكد إن الباسورد مش أقل من 8 حروف.

• commit(): لحفظ التغييرات في الداتابيز فعلياً.
• redirect(url_for("login")): بنحول المستخدم لصفحة الـ login.
• except sqlite3.IntegrityError:: لو حصل خطأ إن الاسم أو الإيميل متكرر (عشان في الداتابيز عاملين UNIQUE). بنطبع رسالة الخطأ.

🔓 الخطوة 4: كود تسجيل الدخول (The Login Route)
@app.route("/login", methods=["GET", "POST"])
def login():
    if request.method == "POST":
        username = request.form["username"].strip()
        password = request.form["password"]
        user = get_db().execute(
            "SELECT * FROM users WHERE username = ?", (username,)
        ).fetchone()

        if user is None or not check_password_hash(
            user["password_hash"], password
        ):
            flash("Invalid username or password.")
        else:
            session.clear()
            session["user_id"] = user["id"]
            return redirect(url_for("dashboard"))
💡 الشرح سطر بسطر:
• SELECT * FROM users WHERE username = ?: بندور على المستخدم في الداتابيز باستخدام الـ Username.
• fetchone(): بترجع أول نتيجة بتتطابق (لو موجودة).
• if user is None or not check_password_hash(...): لو المستخدم مش موجود (None)، أو لو الباسورد اللي كتبه مش متطابق مع الـ Hash المخزن.
• flash("Invalid username or password."): بنطلع رسالة خطأ واحدة (مش بنقول الباسورد غلط ولا الاسم غلط عشان الأمان).
• session.clear(): بنفضي أي بيانات قديمة في الـ Session.
• session["user_id"] = user["id"]: بنخزن الـ ID بتاع المستخدم في الـ Session، وده اللي بيخلي السيرفر يفتكره.
• redirect(url_for("dashboard")): بنحوله للصفحة الرئيسية.
🚪 الخطوة 5: صفحة محمية وتسجيل الخروج (Logout)
@app.route("/dashboard")
def dashboard():
    if "user_id" not in session:
        return redirect(url_for("login"))
    user = get_db().execute(
        "SELECT username FROM users WHERE id = ?", (session["user_id"],)
    ).fetchone()
    return f"Welcome, {user['username']}!"

@app.route("/logout")
def logout():
    session.clear()
    return redirect(url_for("login"))
💡 الشرح سطر بسطر:
• if "user_id" not in session:: ده الحارس (Guard). لو مفيش user_id في الـ Session (يعني المستخدم مش مسجل دخول)، بنحوله لصفحة الـ login.
• SELECT username FROM users WHERE id = ?: بنجيب اسم المستخدم من الداتابيز باستخدام الـ ID اللي في الـ Session.
• session.clear(): دي وظيفة الـ Logout. بمجرد ما بنفضي الـ Session، السيرفر بينسى المستخدم تماماً. وبعدها بنحوله لصفحة الدخول.

✅ قائمة الأمان (Security Checklist)
الإجراء (Action) ليه بنعمله؟ (Why)
Hash and salt استخدم generate_password_hash. متخزنش الباسورد Plain Text أبداً.
Parameterized SQL استخدم علامات ? عشان البيانات متتحولش لكود (حماية من SQL Injection).
One generic error متبينش للمستخدم إذا كان الاسم موجود أصلاً ولا لأ.
HTTPS and cookies شفر الترافيك، وخلي الكوكيز Secure و HttpOnly.
Limit attempts قلل محاولات تخمين الباسورد عن طريق Rate limits أو قفل الحساب مؤقتاً.
CSRF tokens ضيف توكن مخفي في الفورم (مثلاً باستخدام Flask-WTF) لمنع هجمات CSRF.

📌 الملخص (Summary)
  • Registration (التسجيل): تحقق (Validate)، شفر (Hash)، خزن (Store).
  • Login (تسجيل الدخول): دور على المستخدم (Find)، تحقق من الـ Hash (Verify)، ابدأ الـ Session (Start Session).
  • Sessions: بتخلي السيرفر يتعرف على المستخدم في الطلبات الجديدة.
  • Security (الأمان): لازم يكون في تصميمك من أول سطر كود.
💪 جرب بنفسك (Try it yourself)

عشان تتقن المحاضرة دي، جرب تنفذ المهام دي:

  1. ضيف حقل (Confirm Password) في صفحة التسجيل.
  2. اكتب login_required decorator (عشان تستخدمه في أي صفحة عايز تحميها).
  3. اعمل ميزة تقفل الحساب (Lock) بعد 5 محاولات دخول فاشلة.
  4. ضيف عمود (role) في جدول المستخدمين، واعمل صفحة مخصصة للـ Admin بس.
